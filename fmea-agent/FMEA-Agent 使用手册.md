# FMEA Agent 业务使用手册

> 面向项目负责人、工程师、评审员、管理员的日常使用指南。
> 不需要懂代码，跟着手册即可完成从 SOR 文档到 DFMEA 报告的完整 FMEA 分析。

---

## 1. 这是什么产品

**FMEA Agent 是一个 AI 辅助 FMEA 分析平台**：你把 SOR 需求文档交给系统，AI 会引导你一步步完成 DFMEA/PFMEA 七步分析，最终生成可直接使用的 FMEA 报告并导出 Excel。

### 它能帮你做什么

| 能力 | 说明 |
|---|---|
| 自动拆解结构树 | 从 SOR 文档中自动提取 系统→子系统→组件→零件 层级结构 |
| 自动功能分析 | 每个零件/组件的功能由多个 AI 专家并发分析，自动绑定相关法规 |
| 自动失效分析 | 识别每条功能的失效链（失效影响→失效模式→失效原因→失效控制） |
| 标准化风险评估 | 按你公司的 S/O/D 评分标准 + AP 表自动计算 RPN 与操作优先级 |
| 自动生成优化措施 | 对高风险项自动生成预防/探测措施、目标完成日期，并指派责任人 |
| 一键出报告 | 汇总全部数据生成 DFMEA 报告，一键导出 Excel |
| 全程可协作 | 步骤确认、审批、工程师指派、邮件通知，全流程留痕 |

### 适合谁用

- **项目负责人**：建项目、推进各步骤、审批把关
- **工程师**：认领结构树节点、确认功能/失效数据、跟进优化措施
- **评审员**：审核各步骤数据是否合理、审批通过/打回
- **管理员**：账号、角色、团队与智能体管理

## 2. 快速上手（10 分钟跑通）

1. **打开系统**：浏览器访问系统地址（默认 `http://localhost:7777`，由管理员提供）
2. **登录**：使用管理员分配的账号密码
3. **进入工作台**：登录后点击「FMEA 工作台」
4. **创建项目**：在右侧对话框输入：
   > 「创建一个 FMEA 项目，名称：3_6KW，类型：DFMEA，描述：低压电池包」
5. **等待 AI 执行**：AI 创建项目后，左侧项目列表出现该项目
6. **让 AI 做分析**：从 Step 1 结构分析开始，按第 4 章流程逐级推进
7. **生成报告**：最后一步输入「生成报告」，在报告页面下载 Excel

> 全程以「对话」方式操作：你对 AI 说想做什么，AI 自动执行并把结果展示在中间区域。

## 3. 认识工作台

FMEA 工作台（/chat）是核心页面，分三个区域：

```
┌──────────────┬─────────────────────────────┬────────────────┐
│ ① 左侧栏      │ ② 中间内容区                 │ ③ 右侧聊天面板  │
│ · 项目列表     │ · 结构树图（树状图）         │ · 与 AI 对话    │
│ · 七步导航     │ · 功能/失效/风险/优化/报告表格 │ · 执行进度      │
│ · 审批面板     │ · 风险评分文件管理           │                │
└──────────────┴─────────────────────────────┴────────────────┘
```

### 左侧「分析步骤」导航（七步）

| 步骤 | 名称 | 说明 |
|---|---|---|
| 0 | 规划准备 | 创建项目（项目名 = 分析对象） |
| 1 | 结构分析 | 生成产品结构树 |
| 2 | 功能分析 | 每个节点做什么 |
| 3 | 失效分析 | 可能怎么坏、影响什么 |
| 4 | 风险评估 | S/O/D 评分、RPN、AP 优先级 |
| 5 | 优化措施 | 防/探措施 + 责任人 + 完成日期 |
| 6 | 文件化 | 汇总报告 + Excel 导出 |

- 点击步骤可在中间区域查看该步骤的数据
- 已完成的步骤有标识；未生成的步骤会提示「先在对话中引导 AI 完成前置步骤」

### 怎么看结果

- **结构树**：中间区域渲染为树状图，节点可展开/折叠，可选中节点指派工程师
- **各步骤数据**：以表格展示（功能表、失效模式表、风险表、优化措施表）
- **审核状态**：左侧审批面板查看每步的提交/审批状态

## 4. 完整业务流程：跑通一个项目

> 以下以一个新产品项目为例，从 0 到 1 完整走一遍。每一步都给出「你要做什么」和「对 AI 说的话」。

### Step 0 规划准备 —— 创建项目

- **你要做的**：想好项目名（= 要分析的产品/系统，如「12V低压电池系统」）
- **对 AI 说**：
  > 「创建一个 FMEA 项目，名称：12V低压电池系统，类型：DFMEA，描述：xxx 车型低压电池」
- **AI 会做**：创建项目并显示在左侧列表

### Step 1 结构分析 —— 生成结构树

1. **准备 SOR 文档**：把项目的 SOR 需求文档（PDF/Excel 均可）放到一个文件夹
2. **对 AI 说**（初始化知识库）：
   > 「初始化项目知识库，SOR 文件夹路径：D:\SOR\12V电池，项目ID：12V低压电池系统」
3. **对 AI 说**（提取结构树）：
   > 「从知识库提取产品结构树」
4. **AI 会做**：解析全部文档 → 自动提取 系统→子系统→组件→零件 结构 → 画出结构树
5. **你检查**：在树状图中核对层级是否完整、零件是否齐全；不完整可以继续对话让 AI 补充

> 💡 结构树是后面所有分析的基础，**务必检查确认后再进入下一步**。

**指派工程师（可选）**：选中树节点 → 指派给负责该零件的工程师 → 系统自动邮件通知该工程师；工程师登录后可认领确认。

### Step 2 功能分析

- **对 AI 说**：
  > 「对项目 12V低压电池系统 做功能分析」
- **AI 会做**：自动从知识库检索资料，由多个 AI 专家并发分析每个节点的功能，绑定相关法规，汇总校验后存入系统
- **你检查**：功能表是否覆盖所有节点、功能描述是否准确；可让 AI 补充遗漏

### Step 3 失效分析

- **对 AI 说**：
  > 「对项目 12V低压电池系统 做失效分析」
- **AI 会做**：自动读取结构树和功能分析，为每条功能生成失效链：失效影响(FE) → 失效模式(FM) → 失效原因(FC) → 失效控制
- **你检查**：失效模式是否覆盖主要风险场景

### Step 4 风险评估

1. **上传评分标准文件**（重要前置）：
   - 在工作台「风险评分文件」区域上传你们公司的 **SOD 评分标准** 和 **AP 表**（表格/HTML/矩阵格式都可以）
   - ⚠️ 没上传也没关系：AI 会自动使用行业通用的 AIAG/VDA 默认标准
2. **对 AI 说**：
   > 「注册风险评分标准」→「对项目 12V低压电池系统 做风险评估」
3. **AI 会做**：
   - 先读取你上传的文件，提取评分规则（只做一次，之后不再变动）
   - 再逐条计算每条失效的 严重度S / 发生度O / 探测度D / RPN(S×O×D) / 操作优先级AP(H/M/L)
   - 违反法规的项自动高亮；评分标准没覆盖到的项标记「需人工确认」
4. **你处理**：查看「需人工确认」的条目，人工补齐评分

> 💡 风险评估是确定性计算，结果可追溯；确认评分标准正确即可放心使用。

### Step 5 优化措施

- **对 AI 说**：
  > 「对项目 12V低压电池系统 做优化分析」
- **AI 会做**：
  - 自动筛选高风险项（AP=H/M 或违反强制法规）
  - 为每项生成 预防措施 + 探测措施 + 目标完成日期
  - 责任人自动指定为该功能对应的工程师
  - 全部风险可接受时自动跳过（不产生无效措施）
- **你跟进**：在优化措施表中核对责任人、完成日期是否合理

### Step 6 文件化 —— 生成报告

- **对 AI 说**：
  > 「生成报告」
- **AI 会做**：汇总 Step 1~5 全部数据，生成完整 DFMEA 报告；前端展示报告表格，同时生成 Excel 文件
- **你下载**：在报告页面点击导出，得到 `DFMEA_项目名.xlsx`，可直接存档或汇报

## 5. 各角色日常操作

### 项目负责人（Leader）

1. 创建项目（Step 0）
2. 启动/监督各步骤（在对话中让 AI 执行，或关注各步执行情况）
3. 把结构树节点指派给对应工程师
4. 对各步骤数据做最终审批（通过/打回）
5. 跟进优化措施完成情况，导出最终报告

### 工程师（Engineer）

1. 查收邮件通知（被指派节点 / 有步骤待确认）
2. 登录系统 → 认领被指派的节点
3. 核对本人负责的功能/失效/优化措施数据，确认无误
4. 完成分配的优化措施并反馈

### 评审员（Reviewer）

1. 查看各步骤数据（结构树、功能表、失效表、风险表、优化表、报告）
2. 审核合理性，通过或打回（打回需说明原因）
3. 重点关注：风险项是否遗漏、「需人工确认」的评分项

### 管理员（Admin）

1. 「团队管理」页：维护成员（邮箱、知识库授权码）、分配角色、自定义角色权限
2. 「智能体管理」页：查看 AI 智能体架构与运行状态
3. 关注系统健康：有问题时查看第 8 章 FAQ 或联系运维

---

## 6. 审批与协作流程

```
步骤数据生成 → 工程师确认 → 负责人审批 → 进入下一步
     ↑____________ 打回则重新修改 _____________↓
```

- **门控机制**：每步开始前系统自动检查前置步骤是否完成，未完成会被拦截
- **需要确认的步骤**：结构/功能/失效/风险/优化/报告（共 6 步）
- **审批动作**：通过 / 打回（打回后修改可重新提交）
- **邮件通知**：指派节点、待确认事项都会自动发邮件到对应工程师

## 9. 常见业务问题（FAQ）

**Q1：结构树提取得不全/不准？**
结构树是后续所有分析的基础。可以让 AI 重新提取或补充；提取前确认 SOR 文档已完整导入（Step 1 初始化知识库）。

**Q2：没上传 SOD/AP 评分文件，还能做风险评估吗？**
可以。系统自动回退到 AIAG/VDA 行业默认标准。如公司有自定义标准，建议先上传再评估。

**Q3：风险评估里出现「需人工确认」的条目？**
说明该失效的评分不在你提供的标准覆盖范围内（或使用了默认标准）。请人工补齐 S/O/D 评分，系统会重新计算。

**Q4：优化分析提示「跳过」了？**
说明所有风险项均可接受（没有 AP=H/M 或法规违规项），是正常行为，不会产生无效措施。

**Q5：某一步被拦截无法继续？**
前置步骤未完成或未审批通过。按提示先完成前置步骤/等工程师确认。

**Q6：报告 Excel 在哪下载？**
Step 6 完成后，在报告页面点击导出；文件名为 `DFMEA_项目名.xlsx`。

**Q7：想重新跑某一步？**
直接对 AI 说「重新做 xxx 分析」即可，AI 会重新执行并覆盖该步数据。

**Q8：改了数据但页面没变化？**
按 **Ctrl+Shift+R** 强制刷新浏览器（页面有缓存）；若仍无变化，联系管理员重启服务。

## 附录 A：管理员安装配置（简要）

> 面向系统管理员，业务用户可跳过。

1. **环境要求**：Python 3.11+、PostgreSQL、DeepSeek API Key、内网 WeKnora 服务（结构树/功能分析知识源）
2. **配置**：复制 `.env.example` 为 `.env`，填写
   - `FMEA_MODEL_API_KEY`（DeepSeek Key）
   - `FMEA_DB_URL` + `URL_AGENT_DB_*`（PostgreSQL 连接）
   - （可选）`FMEA_NOTIFY_SENDER_EMAIL` / `FMEA_NOTIFY_SENDER_AUTH`（邮件通知，用 SMTP 授权码）
3. **启动**：双击 `start.bat`（自动释放 7777 端口 → 启动 → 健康检查 → 打开浏览器）
4. **首次登录**：默认管理员 `admin / admin123`（请立即修改密码）
5. **数据库**：首次启动自动建表；`db/migrations/` 下的 SQL 需手动执行
6. **改代码后**：后端改动必须重启服务；前端改动需用户强制刷新浏览器
